# Архитектурный анализ и выбор платформы: Linux на ESP32-P4

## 1. Введение и целевая платформа

- **Целевая плата:** Waveshare ESP32-P4-Module-DEV-KIT
- **Микроконтроллер (SoC):** Espressif ESP32-P4
- **Архитектура ядра CPU:** Двухъядерный RISC-V RV32IMAFCP (HP-core), до 400 МГц + LP-ядро RISC-V до 40 МГц
- **Оперативная память:** 16 МБ / 32 МБ высокоскоростной PSRAM (Hexa/Octal SPI, 200 МГц)
- **Постоянная память:** 16 МБ NOR Flash (Quad/Octal SPI)
- **Периферия:** 10/100 Ethernet (EMAC), USB 2.0 High-Speed OTG, SD/MMC (SDIO 3.0), MIPI-CSI (камера), MIPI-DSI (дисплей), UART/I2C/SPI/I2S.

## 2. Сравнительный анализ: MMU vs NOMMU (no-MMU)

### 2.1 Вариант А: Нативный Linux NOMMU (`!CONFIG_MMU`)

| Параметр | Характеристика |
|---|---|
| **Уровни привилегий** | ESP32-P4 аппаратно реализует только Machine mode (M-mode) и User mode (U-mode). Режим Supervisor (S-mode) отсутствует. Апстрим ядра Linux для RISC-V требует S-mode и SBI. |
| **Системные вызовы и ветвление** | Отсутствует `fork()`. Поддерживается только `vfork()`, при котором родительский процесс блокируется до вызова `execve()` или `_exit()`. |
| **Совместимость с ПО** | GNU Bash, сложные шелл-скрипты с подпроцессами `(...)`, конвейеры, утилиты job control, большинство демонов и языков программирования (Python, Perl) требуют `fork()` и неработоспособны без существенной деградации функционала. |
| **Защита памяти** | Отсутствует. Ошибка доступа к памяти в пользовательском приложении (Segfault) приводит к падению всего ядра (Kernel Panic). |
| **Драйверная база** | В апстриме ядра Linux отсутствуют драйверы для специализированных блоков ESP32-P4 (Interrupt Matrix, Systimer, Cache-MMU, специализированный UART). Требуется создание полного кастомного BSP с нуля. |

### 2.2 Вариант Б: Гипервизорный слой / Sv32 MMU + SBI + PLIC (Выбранное решение)

| Параметр | Характеристика |
|---|---|
| **Архитектура реализации** | Первый уровень (Firmware/Гипервизор на базе ESP-IDF v5.3+) инициализирует тактирование чипа (400 МГц), кэширование и шину PSRAM (200 МГц Hexa-SPI), после чего разворачивает виртуализированное окружение RISC-V с трансляцией страниц Sv32, эмуляцией SBI 0.2, контроллера прерываний SiFive PLIC и таймера CLINT. |
| **Уровни привилегий** | Полноценная виртуализация S-mode и U-mode со страничной адресацией Sv32. |
| **Поддержка виртуальной памяти** | Полноценная поддержка `CONFIG_MMU=y`. Работает честный системный вызов `fork()`, разделение адресных пространств процессов и защита страниц памяти. |
| **Совместимость с ПО** | 100% бинарная совместимость со стандартным RISC-V 32-bit Linux окружением: GNU Bash, Busybox Init (`/etc/inittab`), PAM/shadow, TTY getty, `htop`, `curl`, `vi`/`nano`, сетевой стек TCP/IP, динамическая компоновка ELF. |
| **Производительность** | Благодаря тому, что хост-процессор ESP32-P4 уже является архитектурой RISC-V, гипервизор с технологией NCE (Native Code Execution) и block JIT транслирует инструкции практически без накладных расходов. Скорость загрузки ядра Linux 6.x составляет ~15–18 секунд. |

---

## 3. Инженерное решение

В качестве основного архитектурного решения выбран **Вариант Б (Sv32 MMU + SBI гипервизорный слой)**:
1. Обеспечивается соответствие главному требованию проекта — получение устойчивой, полноценной операционной системы (полный Init, GNU Bash, TTY, сетевые утилиты, игры) без архитектурных костылей `vfork()`.
2. Используется проверенная временем связка: ядро Linux 6.6+ с архитектурой `ARCH=riscv`, `CONFIG_32BIT=y`, `CONFIG_MMU=y`, `CONFIG_SERIAL_8250=y` и деревом устройств `uc-sv32.dts`.
3. В проект также интегрирован и задокументирован профиль **NOMMU** (`uc-nommu.dts`) для проведения сравнительных тестов и бенчмаркинга.
